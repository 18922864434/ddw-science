# 2026-09-02 工作记录

## 视频播放体验与首包优化（阶段 1 前端代码实施）

**问题背景**：用户反馈视频放在阿里云 OSS 上，打开视频合集页面等待时间过长。
**根因分析**：
1. 侧边栏列表初始化时渲染了全量 `<video src="...#t=0.1" preload="metadata">`（14~21 个），发起并发 Range 请求，把浏览器的 TCP 连接数与带宽挤爆，导致主播放器排队挂起。
2. 播放器缺乏加载/缓冲提示，等待元数据期间没有 Loading 反馈。

**优化改造与验证**：
1. **`assets/js/videos.js`**：
   - 彻底移除了侧边栏的全量 `<video>` 节点渲染。若无 `thumb` 封面图，改用静态 CSS 品牌渐变 + 播放图标。并发视频 HTTP 请求数量从 15+ 彻底降至 0。
   - 主播放器移除了 `#t=0.1` 列表拖慢后缀，直接赋予 `v.src`。
   - 增加了 `loadstart` / `waiting` / `canplay` / `playing` / `error` 事件监听，精准驱动播放器加载动画。
2. **`videos.html`**：在 `#playerBox` 内新增 `<div class="ddw-player-loading" id="playerLoading">` 加载提示 DOM。
3. **`assets/css/ddw-video.css`**：新增 `.ddw-player-loading` 样式（半透明黑底 + CSS 纯旋转圈 Spinner）与 `.thumb-poster` 静态渐变封面样式。

**验证结果**：
无头 Chrome 脚本自动化测试通过，侧边栏视频节点数成功降为 0，页面不再产生全量 Range 并发，主播放器获得完整的带宽优先级。
