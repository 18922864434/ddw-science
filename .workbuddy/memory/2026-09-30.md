- **度符号形态**：本次按要求使用 `1.5 ℃` = 半角空格 + **U+2103（全角 ℃）**，字节 `31 2e 35 20 e2 84 83`。

  → 站内度符号现已不统一，后续若做全站规范化需留意这一处「有意为之」的差异。
- **en-dash 保持**：`75–80` 的 `–` 仍为 U+2013（`e2 80 93`），未被 Edit 工具改写。
- **行尾符**：`Edit` 工具能正确保留 CRLF（about-ddw 473/473、research 472/472），无需事后修复。
  `robots.txt` 保持纯 LF（CR 字节数 0，LF 28），未被引入 CRLF。
- **`grep -c` 陷阱**：它统计的是**匹配的行数**，不是出现次数。文件末尾无换行符时，
  计数会虚高 1（paper 页 `CR=213 / wc -l=212` 就是这个原因，并非行尾被改）。
  验证「行尾是否被破坏」应看 **`git diff --numstat` 新增/删除行数**——本次每文件 1–3 行，是行尾完好的确证。

### 新踩的坑（已解决）
`git pull --rebase origin master` 报 `fatal: Cannot rebase onto multiple branches.`，
且**把远端 `state.json` 直接暂存进了索引**（`git status` 显示 `M`）。
原因是该仓库当时**没有设置 `branch.master.remote` / `branch.master.merge`**，pull 无法确定单一上游。
- 处置：先 `git diff HEAD -- <file>` 确认内容 = 远端 bot 版本，再 `git checkout -- <file>` 丢弃，
  最后改用 **`git rebase origin/master`**（显式 upstream，绕开 pull 的多分支歧义）→ 成功，`git push` 通过。
- **教训**：push 被拒时不要用 `git pull`（在配置不完整的仓库里会误暂存）；
  统一用 `git fetch` + `git rebase origin/master`，风险最低、可控。

### 已落地的仓库配置（避免复发）
- `pull.rebase = true`（此后 `git pull` 等价于 `--rebase`）
- `push.default = current`（配合已有的 `branch.master.merge=refs/heads/master`，`git push` 不再报无上游）
