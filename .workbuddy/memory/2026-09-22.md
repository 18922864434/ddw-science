## 为 ddw-science.com 接入 IndexNow（全量 + 增量推送）

**前期核实（在线实测，结论决定了设计）：**
- 站点托管于 Cloudflare（Pages 形态）。实测 `https://ddw-science.com/scientist` 返回 200，而 `scientist.html` 返回 **308** 跳转到无扩展名地址；`videos.html?c=...` 同样 308。

### 第三轮：定位并修复指纹校验缺陷

首次全量推送暴露两个问题，均已修复：

- **Cloudflare RUM beacon 注入**（根因，影响全部页面）：带 HTML `Accept` 头请求时，CF 会在 `</body>` 前注入 `static.cloudflareinsights.com/beacon.min.js`（实测 `/videos` 8713 vs 8346 字节，差 367 字节）。这导致 26 个页面指纹**确定性**不匹配、空耗 180s。修复：在 `contentSignature()` 中按 `cloudflareinsights.com` / `data-cf-beacon` / `/cdn-cgi/` 属性剥离该脚本（其 src 含构建版本号，不能按整串匹配）。修复后 **26/26 在 1.6s 内确认**。
  - 定位方法值得复用：同一 URL 换请求头后指纹由不符变为相符 → 排除缓存与部署延迟，锁定服务端内容协商。
  - 曾一度误归因为"边缘节点传播延迟"，实为确定性注入，已在文档中显式纠偏。
- **Cloudflare 邮箱混淆**（仅 `/contact`）：`info@hyd.hu` 等被就地改写为 `email-protection` 形式（12138 vs 11759 字节），剥离脚本无法还原 → 列入 `liveCheck.ignoreUrls`。
- **等待语义改进**：由"死等到超时"改为**收敛即退出**（连续 3 轮无进展即结束，`stagnantLimit`），最坏空耗从 180s 降至约 40s。
- **未关闭 CF 功能**：RUM 与邮箱混淆均属既有线上行为，关闭等于改变对外契约，不应由工具单方面决定。

### 第六轮：BWT 无 IndexNow 数据的原因排查

**用户现象**：Bing Webmaster Tools → IndexNow 页面只显示 "Get Started" 引导页与营销文案，无提交数据。

**我方提交时间线（北京时间，取自 logs/*.jsonl）**：
- 15:41:43 — CI 增量推送，**202**（首次提交，密钥校验待处理），26 个 URL
- 15:46:13 — 本地全量推送，**200**，27 个 URL
- 16:29:51 — 本地全量 `--force`，**200**，27 个 URL
- `BingSiteAuth.xml` 于 **~16:29** 才上线（此前 BWT 无法验证站点）

**结论：提交侧无问题**（均 200/202，密钥预检通过）。无数据的原因是 BWT 侧的前置条件与延迟：

1. BWT 的 IndexNow 报告**只对已在其账号中验证过的站点生效**；未验证时提交可被 API 接受（200），但无处归属。而本站的 Bing 验证文件 16:29 才上线。
2. **两次成功提交都发生在验证之前或同一时刻**（15:46、16:29:51），可能不会回溯归属。
3. BWT 报告本身有**处理延迟**，实践者普遍反馈数小时至 24–48h 才反映出来。
4. 该页面显示的 "Get Started" + "WHY INDEXNOW?" 是**未配置/无数据时的引导态**，不代表提交失败。

**协议约束（重要，已据此收紧工具使用策略）**：官方 FAQ 明确「重复提交未发生实质变更的 URL」可能返回 **422**。因此：
- 不应连续用 `--force` 反复重推同一批未变更 URL；
- 正确顺序是「内容变更 → 推送」，而非「为了让面板出数据而反复推送」；
- 若验证后长时间仍无数据，再间隔较久（数小时以上）补推一次，而不是密集重试。

**给用户的 BWT 侧动作**：① 确认站点已显示为已验证；② 在「网站地图」提交 `https://ddw-science.com/sitemap.xml`（与 IndexNow 独立，提供基线清单）；③ 用「URL 检查」看单页抓取状态；④ 数小时后再看 IndexNow 报告。
