## 为 ddw-science.com 接入 IndexNow（全量 + 增量推送）

**前期核实（在线实测，结论决定了设计）：**
- 站点托管于 Cloudflare（Pages 形态）。实测 `https://ddw-science.com/scientist` 返回 200，而 `scientist.html` 返回 **308** 跳转到无扩展名地址；`videos.html?c=...` 同样 308。
- 由此确定：IndexNow 必须提交**剥离 `.html`** 的最终 URL，且必须丢弃 `?c=` 查询变体。
- 发现 P0 缺陷：26 个页面的 `canonical` 指向会被 308 的 `*.html` 地址，与 sitemap（无扩展名，形态正确）冲突。**未擅自修改**，已写入方案待确认。
- 发现 P1 缺口：`sitemap.xml` 缺少 `/videos`（只有两个 `?c=` 变体）。

**交付内容：**
- 新增 `tools/indexnow/`：`cli.mjs`（编排）+ `lib/urls.mjs`（归一化/去重/文件↔URL 映射/git diff 采集）、`lib/submit.mjs`（状态码语义化/分批/退避重试/密钥预检）、`lib/state.mjs`（TTL 去重/记账/清理）、`lib/live.mjs`（线上校验/部署生效等待）、`lib/util.mjs`（哈希/日志/退避）。
- 新增密钥文件 `5c3ba58f7e6bfd43cda9374ce850898a.txt`（根目录，32 字节无换行）。
- 新增 `.github/workflows/indexnow.yml`：push 增量、manual 全量、每周一 09:00 兜底、状态回写（GITHUB_TOKEN 推送不触发循环）、报告归档。
- 新增 `tools/indexnow/README.md`：完整方案（现状核实、能力边界、数据流、接口密钥、全量/增量流程、模块清单、去重、重试、分步上线、风险）。

### 第二轮：执行修复与上线

1. **修正范围比原计划更大**：审计发现 `.html` 自引用不止 canonical，共 **140 处 / 26 个文件**——含 `canonical`、`hreflang alternate`、JSON-LD 面包屑与条目，另有 `llms.txt` 10 处、`conferences.html` 两处相对链接 `videos.html?c=`。全部改为无扩展名形态。
2. **行尾符陷阱（重要教训）**：仓库 HTML 使用 **CRLF**，`sed -i` 会改写成 LF，导致整文件被判定为重写（`publications.html` 一度产生 788 行 diff、累计 28 文件）。已用脚本按 HEAD 原始行尾还原，最终 diff 收敛为 153 插入 / 159 删除。**今后批量改写本仓库 HTML 必须做行尾还原。**
3. **sitemap**：两条 `videos.html?c=` 变体合并为单条 `/videos`。修正后 sitemap 与站点扫描均为 27 条，与 canonical 集合零差集（用 Python 解析 XML 实测核对）。
4. **提交**：拆为两个 commit（`21f4689` URL 形态修正 / `f7422e1` IndexNow 工具链），已推送 master。
5. **上线验证**：密钥文件 `curl` 返回 200 且内容一致；线上 canonical / hreflang / sitemap / llms.txt 均已生效。
6. **首次真实全量推送**：`api.indexnow.org` 返回 **200**，27 个 URL 全部提交，退出码 0。TTL 去重随后复跑正确跳过全部 27 条。

### 第三轮：定位并修复指纹校验缺陷

首次全量推送暴露两个问题，均已修复：

- **Cloudflare RUM beacon 注入**（根因，影响全部页面）：带 HTML `Accept` 头请求时，CF 会在 `</body>` 前注入 `static.cloudflareinsights.com/beacon.min.js`（实测 `/videos` 8713 vs 8346 字节，差 367 字节）。这导致 26 个页面指纹**确定性**不匹配、空耗 180s。修复：在 `contentSignature()` 中按 `cloudflareinsights.com` / `data-cf-beacon` / `/cdn-cgi/` 属性剥离该脚本（其 src 含构建版本号，不能按整串匹配）。修复后 **26/26 在 1.6s 内确认**。
  - 定位方法值得复用：同一 URL 换请求头后指纹由不符变为相符 → 排除缓存与部署延迟，锁定服务端内容协商。
  - 曾一度误归因为"边缘节点传播延迟"，实为确定性注入，已在文档中显式纠偏。
- **Cloudflare 邮箱混淆**（仅 `/contact`）：`info@hyd.hu` 等被就地改写为 `email-protection` 形式（12138 vs 11759 字节），剥离脚本无法还原 → 列入 `liveCheck.ignoreUrls`。
- **等待语义改进**：由"死等到超时"改为**收敛即退出**（连续 3 轮无进展即结束，`stagnantLimit`），最坏空耗从 180s 降至约 40s。
- **未关闭 CF 功能**：RUM 与邮箱混淆均属既有线上行为，关闭等于改变对外契约，不应由工具单方面决定。
