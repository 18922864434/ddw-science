## 诊断：Chrome 无法播放远程 Metabolism.mp4（HTTP/2 传输缺陷）

**现象**：`<video src="https://preventa-website.idhealth.cn/uploads/video/lectures/Metabolism.mp4#t=0.1">`
在用户 Chrome 上 `loadedmetadata` 永不触发，readyState 卡 0，无限 seek 循环（每读一段就 ERR_ABORTED）。

**诊断链（逐层排除，全部实证）**：
1. 文件 ✅：完整下载（104,284,290 B）后本地 HTTP 服务器播放成功（1576s / 1080p / readyState=4）；
   fMP4 结构标准（ftyp→moov→(moof+mdat)*n）、H.264 avc1 + AAC mp4a、mvex/trex 齐全。
2. 服务器 HTTP 层 ✅：H1/H2 均返回正确 206 + video/mp4 + Content-Range；大偏移
   （458752/786432/1114112）字节与请求逐字节一致；Node http2 无上界流式读取稳定 ~3MB/s。
3. 代理 ✅ 排除：系统代理 127.0.0.1:7890（Clash），但 Chrome `--no-proxy-server` 直连同样失败。
4. QUIC ✅ 排除：`--disable-quic` 无效。
5. Chrome H2 媒体栈 ✅：本地 Node `http2.createSecureServer`（H2-only，自签名证书，端口 8098）
   播放同一文件成功——即使 MIMIC nginx 响应头（server/etag/double cache-control/set-cookie）也成功；
   且成功播放时 Chrome 同样发 200+ 个递增偏移 Range 请求 → 大量 seek 是正常行为，非故障信号。
6. **唯一定位：远程 nginx（或前置网关）在 HTTP/2 下对 Range 视频流的响应与 Chrome 媒体栈交互异常。**
   证据：同一 Chrome 远程 H1（`--disable-http2`）播放成功（currentTime 推进、readyState=4），
   远程 H2 失败；Node H2 客户端远程正常；Chrome H2 本地正常。
   netlog 证据：每个 source 都收到正确 `content-range: bytes X-104284289/104284290`，无 RST_STREAM/GOAWAY，
   Chrome 主动 CANCELLED 后陷入 seek 循环。

**结论**：前端代码与文件均无问题，无法用前端 JS 强制 Chrome 降级 HTTP/1.1。
修复必须在服务器侧：nginx 对 `/uploads/video/`（或 `/uploads/`）路径关闭 HTTP/2
（`listen 443 ssl;` 去掉 http2，或独立 server 块/按 location 处理），或排查 CDN/WAF/代理层 H2 中继。

**可复用方法论（Chrome 媒体播放排查）**：
- 协议二分法：`--disable-http2` / `--disable-quic` / `--no-proxy-server` 逐一开关定位。
- 本地对照实验：完整下载文件 → 本地 HTTP 服务器 → 本地 H2-only 服务器（MIMIC 远程响应头），
  用「成功对照组」反推故障点，比纯观察快得多。
- netlog：`--log-net-log + --net-log-capture-mode=IncludeSensitive`，事件 type 是数字枚举，
  从 `data.constants.logEventTypes` 映射（134=URL_REQUEST_START_JOB、243=READ_RESPONSE_HEADERS）。
- Windows 坑：Git Bash heredoc 写 JS 会吞反斜杠（必须用 Write 工具）；node 不识别 Git Bash /tmp
  （一律写 `C:\Users\...\AppData\Local\Temp\` 绝对路径）；bash 内调 PowerShell 被安全拦截（用 PowerShell 工具）；
  file:// 播放被 Chrome URL safety check 拒绝（用本地 http/https 服务器）。
- puppeteer-core 复用系统 Chrome，避免下载 Chromium。

**待办**：lec-14（LungCancer.mp4）正确文件名待用户提供后更新 video-config.js 并复测；
本文件锁定的 H2 差异点（SETTINGS/WINDOW_UPDATE/流控窗口）如需深挖可抓 nghttp2 -v 帧级数据。
